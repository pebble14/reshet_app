# Windows 공개 베타 준비

## 2026-11-04 공통 데이터 업데이트 후보

- Windows와 Android는 데이터 버전 `2026.11.04`, seed SHA256 `014d48c6d53a6948a149986a39d21497e07163a76f8b8bf06fc619f1c6717791`을 함께 사용한다.
- 사용자가 가져온 최신 작업 DB에서 관계 ID 7546의 의미 없는 시험용 `note`·`source` 두 값만 NULL로 정리했다. 백업과 전체 비교로 다른 데이터·schema·작업 편집 이력 보존을 확인했다.
- 공식 prepare/promote 절차로 발음 보류 11개·RMAC 정책을 적용하고 후보에서 편집 이력 7,521건을 제거했다. 기존 seed는 자동 백업했다.
- 앱·프로그램 정보 버전은 `1.0.0+3`이다. Android 업데이트와 버전 표시를 맞추기 위해 Windows도 다시 빌드했다.
- 배포 후보: Git 제외 `build/common_release_20261104/public/`. 원본 백업·검증 보고서는 상위 비공개 폴더에 보관하며 배포하지 않는다.
- 사용자가 새 Windows 빌드의 정상 작동을 확인했다고 보고했다. 확인 주체는 사용자이며 Codex가 직접 수행한 UI 테스트는 아니다.
- 사용자 승인 후 [Windows 공개 베타](https://github.com/pebble14/reshet_app/releases/tag/v1.0.0-beta.1)를 게시했다. 태그 `v1.0.0-beta.1`은 소스 커밋 `7de2567c66dbb8647890605501e49363a5147dc8`에 고정됐다. Windows 앱 ZIP·DB ZIP·Windows 전용 `SHA256SUMS.txt`를 첨부했다. Android AAB와 비공개 백업·보고서는 첨부하지 않았다.

이 문서는 Windows x64 ZIP과 별도 데이터 다운로드를 준비하는 배포 절차다. 실제 게시·기존 저장소의 이력 정리·공개 전환은 검토한 산출물과 사용자 승인 범위에서 진행한다.

## 배포물

- 앱 ZIP: Release 실행 파일·DLL·Flutter data 폴더·필요한 Visual C++ 런타임과 코드 MIT·데이터 이용 조건·자료 출처·개인정보 안내를 포함한다.
- 별도 DB ZIP: 앱 번들에 포함한 것과 동일한 `reshet_seed.db`, 자료 버전·작성일·SHA256, 데이터 이용 조건과 출처 안내를 제공한다.
- Git에는 DB를 추가하지 않는다. 개발자의 작업 DB와 이력·백업·후보 비교 보고서는 공개 패키지에 포함하지 않는다.

ZIP 배포는 `reshet.portable` 표시 파일을 넣지 않는 일반 모드를 기본으로 한다. 데이터는 `%LOCALAPPDATA%\Reshet\data`에 보관한다. 프로그램 폴더를 바꿔도 기존 사용자 DB를 유지한다. 이 계약은 [SCHEMA](../database/SCHEMA.md)를 따른다.

## DB 후보와 패키지 조립

앱·DB 편집기를 닫고 [공식 seed 준비 절차](../database/SEED_RELEASE.md)의 `prepare`로 최신 작업본의 후보를 만든다. 승인 발음 보류·RMAC 한글 번역·후보의 편집 이력 제거는 기존 정책을 그대로 적용한다. 후보 보고서는 개발자 검토용으로만 보관한다.

2026-10-17 공개 베타 준비에서는 원본 work·현재 seed·공식 후보를 보존하고 별도 배포 사본만 사용한다. 사용자 승인에 따라 관계 ID 7546(`G2424_0000` → `L0000_0159`)의 `note='테스트용 노트'`, `source='테스트용 소스'` 두 값만 배포 사본에서 NULL로 비운다. 관계·설명·상태·방향·시각과 나머지 데이터는 보존한다. 이 사본은 기존 seed 승격 보고서를 변조하거나 `promote`로 우회 승격하지 않는다. 별도 배포 변환으로 기록하고 전체 표·schema 비교에서 이 두 필드만 다른지 확인한다.

Windows Release를 빌드한 뒤 새 배포 폴더로 필요한 파일만 복사한다. 배포 폴더의 `data/flutter_assets/data/reshet_seed.db`에는 검증한 배포 사본을 배치한다. 원래 build 폴더·프로젝트 seed는 변경하지 않는다. 앱 ZIP과 별도 DB ZIP의 seed SHA가 같은지 확인하고 조립 절차·버전·빌드 번호·입력 SHA·파일별 SHA를 배포 manifest에 기록한다.

실제 runtime 매핑은 `data/flutter_assets/NativeAssetsManifest.json`을 확인한다. Windows x64의 sqlite3 매핑은 앱과 함께 배치한 `sqlite3.dll` 이름이어야 한다. Release 루트에 테스트 실행의 호스트 절대 경로가 남은 개발용 `native_assets.json`이 복사돼 있으면 배포 사본에서는 제외하고 runtime manifest는 보존한다. `.pdb`와 개발용 파일도 패키지에서 제외한다.

기본 실행 파일명은 현재 Windows runner의 `study.exe`다. 서명하지 않은 베타는 서명 상태를 안내하며 서명된 파일이라고 표현하지 않는다. Visual C++ 런타임이 필요한 경우 배포 가능한 runtime 파일을 확보하고 개발 도구가 없는 PC에서 확인한다.

## 공개 소스와 이메일 보호

사용자 승인에 따라 기존 `pebble14/reshet_app` 저장소를 계속 개발·배포의 기준으로 사용한다. 별도 공개 소스 저장소는 만들지 않는다. 공개 전에 원본 Git 이력·모든 refs·로컬 작업 브랜치와 DB를 Git 미추적 비공개 백업으로 보존한다.

별도 사본에서 모든 원격 브랜치의 과거 개인 이메일을 정리한다. 커밋 작성자·커미터 이메일은 GitHub `noreply` 주소로, 파일 본문의 공개 문의처는 `reshetcontact@gmail.com`으로 통일한다. 커밋 내용·부모 관계·브랜치·날짜를 보존하고, 변경으로 무효화되는 서명과 커밋 SHA 변경은 검증 결과에 기록한다. 옛 SHA와 새 SHA의 대응표는 비공개 백업에 보관한다. 원격 반영에는 각 ref의 예상 SHA를 지정한 `force-with-lease`를 사용하며 작업 도중 다른 변경이 있으면 덮어쓰지 않는다. 브랜치를 임의 삭제하지 않는다.

공개 전 검증은 최신 파일뿐 아니라 정리된 전체 이력과 모든 브랜치를 대상으로 한다. 사용자는 2026-11-03 옛 이메일 객체가 남아 있어도 기존 저장소를 공개하기로 결정했고 실제 Public 전환을 완료했다. 옛 객체의 서버 측 삭제 요청은 별도로 계속 확인하며 완전 제거로 보고하지 않는다. `reshet-info`의 과거 개인정보처리방침도 같은 삭제 확인 대상이다.

로컬 작업 브랜치와 원격 추적 refs를 정리된 SHA에 맞추고, 이 저장소의 향후 Git 커밋 이메일도 `noreply`로 설정한다. GitHub 계정의 로그인 이메일·비밀번호·2단계 인증은 변경하지 않는다. 공개 파일에 DB·서명 자료·로컬 캐시·빌드·백업을 넣지 않는다. 원본 work·seed DB와 사용자 DB는 그대로 보존하며 기존 공개 안내 링크는 같은 저장소 주소를 사용한다.

## 실제 PC 확인

개발 도구가 없는 Windows x64 PC 또는 격리된 Windows 계정에서 확인한다. 기존 데이터가 있으면 먼저 앱의 백업 기능으로 별도 위치에 저장한다.

1. ZIP을 완전히 풀고 프로젝트 폴더와 무관한 위치에서 `study.exe`를 실행한다. DB 초기화 오류나 DLL 누락 없이 시작해야 한다.
2. `G0026`(아가페·사랑)을 검색하고 상세를 연다. 이어서 `H0053`(압살롬)의 그래프와 연결 단어를 탐색한다.
3. 테스트용 메모를 기록하고 앱을 종료한 뒤 다시 실행한다. 메모가 유지되어야 한다.
4. DB를 새 파일로 백업하고, 메모를 바꾼 뒤 그 백업을 복원한다. 백업 시점의 메모로 돌아와야 한다.
5. 프로그램 파일만 별도 폴더로 복사한 뒤 실행한다. 같은 Windows 계정의 기존 DB·메모가 유지되어야 한다.
6. 프로그램 정보에서 개인정보처리방침·자료 출처·소프트웨어 라이선스를 읽을 수 있어야 한다.

실패하면 오류 문구와 어느 단계에서 발생했는지 기록한다. 이 확인은 명령어 기반 검사와 구분하며, 실제 수행 전에는 완료로 보고하지 않는다. 확인 후 공개 베타 게시와 소개 페이지 다운로드 링크 갱신을 진행한다.

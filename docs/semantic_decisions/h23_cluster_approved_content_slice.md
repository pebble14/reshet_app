## 핵심 판단 근거

H0023의 canonical occurrence 한 건과 H0043의 세 건은 모두 고유명사 용례다. 각 항목에서 한국어 성경의 `아비아삽`·`에비아삽`과 원문에 가까운 `아비아사프`·`에브야사프`는 서로 다른 lexical sense가 아니라 같은 이름의 관용 표기와 원문 기반 표기다. 따라서 별도 meaning 행이나 slash로 나누지 않고, H5 인명 결정과 같은 가운데점 병기 방식으로 한 행에 보존했다.

Canonical Strong은 H0023을 H0001과 H0622에서 온 이름으로 직접 분석한다. 승인된 `아비-아사프`의 하이픈은 히브리어 정서법의 실제 maqqef를 재현하는 기호가 아니라 합성 경계를 드러내는 한국어 분석 표기다. 반면 H0043은 H0023의 축약형으로, 축약된 표면형에 투명한 구성 경계를 다시 세우기 어렵다. 따라서 `에브-야사프`나 `에브야-사프`를 만들지 않고 `에브야사프`로 붙여 썼다.

동일한 canonical source는 H0023이 H0001·H0622에서 왔고 H0043이 H0023의 축약형이라고 qualifier 없이 명시한다. 이에 구성 요소에서 합성 이름으로 향하는 H0001→H0023·H0622→H0023과 원형에서 축약 변이로 향하는 H0023→H0043을 `asserted`로 승인했다. DB의 canonical pair 정렬 때문에 H0622→H0023은 H0023·H0622 순서와 `w2_to_w1`로 저장한다.

## 채택하지 않은 주요 대안

- 관용 표기와 원문 기반 표기를 별도 meaning 행으로 나누지 않았다. 두 행은 서로 다른 의미처럼 표시되지만 실제 차이는 이름 표기 방식이기 때문이다.
- `아비아삽/아비-아사프`, `에비아삽/에브야사프`처럼 slash로 병기하지 않았다. slash는 의미·번역 대안의 분기로 읽힐 수 있어 동일 인명의 표기 병기에는 가운데점이 더 적절하다.
- H0023의 원문 기반 표기를 `아비아사프`로만 두지 않았다. 이 표기도 가능한 직접 음역이지만 사용자가 합성 구조를 meaning에서 드러내기로 결정했으므로 분석형 `아비-아사프`를 채택했다.
- H0043을 `에브-야사프` 또는 `에브야-사프`로 분절하지 않았다. H0023의 축약형이라는 근거는 있지만 축약 후 표면형에서 그런 경계를 직접 확정할 근거는 없다.
- 앞선 연구에서 제안한 비고는 이번 승인에 포함하지 않았다. 사용자는 relation 추천안과 meaning 표기만 확정했으므로 expression/transliteration과 비고는 기존 값을 보존했다.
